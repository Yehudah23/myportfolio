# Deploy to Render.com

This guide walks you through deploying your portfolio project to Render.com with Docker.

## Prerequisites

- GitHub account with your portfolio repo pushed
- Render.com account (free tier available)

## Option 1: Deploy via Render Dashboard (Easiest)

### Step 1: Connect GitHub to Render
1. Go to [render.com](https://render.com) and sign up/log in
2. Click **New +** → **Blueprint**
3. Click **Connect Repository**
4. Authorize GitHub and select your `myportfolio` repository

### Step 2: Create Blueprint Deployment
1. Select the repository
2. Render will detect `render.yaml` automatically
3. Review the services:
   - **myportfolio-web**: Docker web service
   - **myportfolio-db**: MySQL database (free tier)
4. Click **Create Blueprint**
5. Render will automatically deploy both services

### Step 3: Configure Environment Variables
After deployment starts, go to your web service settings:

1. Navigate to **Environment** tab
2. Render will auto-populate `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS` from the MySQL service
3. No manual configuration needed if using render.yaml

For authenticated browser requests from a separate frontend (like Vercel), the frontend must send cookies:

```js
fetch('https://myportfolio-amie.onrender.com/php/preferences.php', {
   credentials: 'include'
})
```

### Step 4: Wait for Database Initialization
1. The database service will start and auto-initialize with `database.sql`
2. Check logs: **Logs** tab → Select **myportfolio-db**
3. Wait for "ready to accept connections"

### Step 5: Access Your App
- **Web URL**: Will be shown in Render dashboard (e.g., `https://myportfolio-xxxx.onrender.com`)
- **Admin Login**: 
  - Username: `admin`
  - Password: `yehudah23`

## Option 2: Manual Deployment (More Control)

### Step 1: Create Web Service
1. **New +** → **Web Service**
2. Select **Deploy existing code from a repository**
3. Connect your GitHub repo
4. Name: `myportfolio-web`
5. Runtime: **Docker**
6. Docker: Should auto-detect `Dockerfile`
7. Plan: **Free** (or Starter)

### Step 2: Create MySQL Database
1. **New +** → **MySQL**
2. Database name: `my-portfolio`
3. Username: `portfolio_user`
4. Plan: **Free**
5. Create the database

### Step 3: Connect Database to Web Service
1. Go to Web Service → **Environment**
2. Add environment variables:
   ```
   DB_HOST=<MySQL internal hostname>
   DB_NAME=my-portfolio
   DB_USER=portfolio_user
   DB_PASS=<auto-generated password from MySQL>
   ```
3. (Render shows these values in MySQL dashboard)

### Step 4: Deploy
1. Click **Deploy**
2. Render builds the Docker image and deploys it
3. Wait for "Live" status

---

## Environment Variables Reference

| Variable | Value | Example |
|----------|-------|---------|
| `DB_HOST` | MySQL hostname | `dpg-xxxxx.render.internal` |
| `DB_NAME` | Database name | `my-portfolio` |
| `DB_USER` | MySQL user | `portfolio_user` |
| `DB_PASS` | MySQL password | `auto-generated` |
| `ALLOWED_ORIGINS` | CORS origins | `https://myportfolio-xxxx.onrender.com` |

## Troubleshooting

### Database Connection Failed
- **Check logs**: Go to MySQL service → **Logs**
- **Wait**: MySQL takes 30-60 seconds to initialize
- **Verify credentials**: Match DB_* environment variables

### "Invalid JSON" on Project Create
- Ensure `CORS` headers are configured correctly
- Check `ALLOWED_ORIGINS` includes your Render domain
- Verify `Content-Type: application/json` in API requests

### Database Import Failed
- Check MySQL service logs for errors
- Ensure `database.sql` exists in repository root
- Manually run SQL if needed:
  ```bash
  mysql -h <host> -u <user> -p <database> < database.sql
  ```

### App Won't Start
- Check build logs: **Build & Deploys** → **Build Logs**
- Common issues:
  - Missing `Dockerfile` (check it's in repo root)
  - PHP extension errors (verify `php -l php/*.php`)
  - Port conflicts (Render uses port 80)

### Cold Starts
- Free tier services auto-pause after 15 min inactivity
- Page takes 20-30 seconds to restart
- Upgrade to **Starter** plan to prevent pausing

## Production Checklist

- [ ] Update `CONTACT_EMAIL` and `FROM_EMAIL` in environment
- [ ] Set strong `DB_PASS` (auto-generated is fine)
- [ ] Enable backups: MySQL service → **Backups** tab
- [ ] Monitor usage: **Metrics** tab
- [ ] Set up custom domain (if desired)
- [ ] Enable auto-deploys: **Deploys** → **Connect repo**

## Monitoring & Logs

### View Logs
1. Web service: Click **Logs**
2. Database: Click database name → **Logs**
3. Build: **Build & Deploys** → Select deployment

### Monitor Metrics
1. **Metrics** tab shows CPU, memory, network usage
2. Free tier has limited history (24 hours)

### Enable Auto-Deploy
1. Web service → **Settings**
2. **Auto-Deploy**: Select branch (e.g., `main`)
3. Now every push triggers a rebuild

---

## Updating Your App

1. **Make changes locally**
   ```bash
   # Edit files, test locally
   git add .
   git commit -m "Update feature"
   git push origin main
   ```

2. **Render auto-deploys** (if auto-deploy enabled)
   - Or manually: Web service → **Manual Deploy** → Select branch

3. **Database migrations**: Manually run SQL via MySQL CLI or Render dashboard

---

## Cleanup / Stopping Services

- **Suspend**: Service → **Settings** → **Suspend** (keep data)
- **Delete**: Service → **Settings** → **Delete** (removes everything)
- **Delete backup**: MySQL → **Backups** tab
